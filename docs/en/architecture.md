# How the firmware works

[Українською](../uk/architecture.md) · [Documentation index](README.md)

## Where the code comes from

The **Clock Informer 2.7.1** firmware for ESP32 (by [Semen_p](https://www.thingiverse.com/thing:3924947), licensed
CC BY-NC 4.0) is distributed as ready-made firmware files; the author does not publish the source of the ESP32 version.
The code in this repository was reconstructed from the 2.7.1 machine code:

- functions were decompiled (Ghidra) and rewritten in C++ for the same Arduino-ESP32 1.0.4 core and the same libraries;
- all 376 of the author's functions were compared with the original at machine-code level (calls, globals, strings,
  constants): 120 have no meaningful difference at all, the rest differ mostly in how the compiler laid out temporary
  strings, ArduinoJson templates and inlined functions; key functions (clock face, button, saving settings, weather,
  etc.) were checked by hand along every branch;
- fonts — byte for byte; display library functions — 115 of 126 byte-identical; the author's 10 display effects —
  identical behaviour in a Xtensa emulator (2000 random scenarios, every display column after every step);
- the reconstructed copy was tested on a real clock.

The **`reconstructed-2.7.1`** tag is this copy with the original's behaviour (including its bugs). Everything changed
after it is visible in the git history from that tag: `git diff reconstructed-2.7.1 v1.0.0`.

### Reading the code

- `g_c34ba` — a global variable of the original; the number is its RAM address (`0x3ffc34ba`). Meanings are in `g.h`.
- `// @4011bb90` before a function — the function's address in the original firmware; `f_400e3500` — a function not
  given a meaningful name yet.
- `// Виправлено: …` (“Fixed”) — what was wrong in 2.7.1 and what changed; `(нове, не з оригіналу)` (“new, not from the
  original”) in a file header — a new module.
- `ghidra.h` — decompiler types, so the ported code keeps the same type conversions as the original.
- Every file starts with a Ukrainian description and an `// EN:` line in English. Comments are in Ukrainian.

## Fixes to 2.7.1 bugs

| What it was | What it is now | Where |
|---|---|---|
| Without internet the main loop stalled for up to ~3 min (a check without timeout); the watchdog restarted the clock | TCP check to 8.8.8.8 and 1.1.1.1, 1.5 s each, then HTTP with a 3 s connect timeout; “offline” only after two failures | `wifi.cpp` |
| Every ~6 min without internet — a Wi-Fi reconnect even when the router was fine; web connections dropped | reconnect only when the router itself does not answer | `wifi.cpp` |
| After a Wi-Fi drop the clock switched Wi-Fi off and became an access point within 8 s | a new drop counts attempts from zero, the first own attempt after 5 s | `wifi.cpp` |
| The core 1.0.4 DNS could write into the stack of a function that had already returned — random crashes | lookup through the lwIP thread, waiting for the result (`--wrap` `hostByName`) | `netfix.cpp` |
| The weather/news HTTPS client connected without a timeout — the loop stalled for minutes | connect for at most 10 s (`--wrap` `lwip_connect`) | `netfix.cpp` |
| The whole service block waited for a news item to finish scrolling (2–4.5 min): brightness, night, morning, network recovery | fast tasks run every loop; network tasks after the animation, but no later than 5 min | `core.cpp` |
| `parsePacket()` every loop without a DNS server: ~180 lines/s on Serial, jerky animation, fragmented memory | the captive-portal DNS runs only when it is started | `core.cpp` |
| Any system time after 2021 was taken as “from NTP”: after a restart — stale time, then a jump | wait for a fresh NTP reply (SNTP counter, `--wrap` `settimeofday`) | `time.cpp`, `netfix.cpp` |
| Time zone and summer time were applied only at sync time; the “Summer time” switch “did nothing” | changes apply immediately; new “Auto” mode (EU rules) | `timefix.cpp` |
| Hourly voice: the first announcement was “eaten”, “Now” without the hour, announcements at random minutes; “Voice test” played a random hour | announcements only at the top of the hour and with a known time; the test announces the current time | `sound.cpp` |
| An alarm at night rang with the display off | the display turns on while ringing | `sound.cpp` |
| The button did not stop the DFPlayer alarm melody when the confirmation files were missing on the card | the melody stops | `sound.cpp` |
| A message at night turned the display on and it stayed on until morning | after the message the display goes dark again | `display_misc.cpp` |
| A stray dot at 9:59→10:00 on the sliding-digits clock face | clock columns stay inside its own zone | `clock_slide.cpp` |
| Interface cache tag by version (`h2.7.1`): after an update — the old interface from the browser cache | tag by content | `web.cpp`, `webui_patch.py` |
| The live console showed Wi-Fi passwords from `/networks.json` | `password` values are masked | `ws.cpp` |

## New features

![Start-up status on a two-floor display (Ukrainian text)](../images/status_1.gif)

| What | How | Where |
|---|---|---|
| Start-up status on the display | while the clock waits for the network, a separate FreeRTOS task shows an animated icon and text (two floors: icon on top, text below) | `status.cpp` |
| Smooth brightness | photoresistor sampled every 100 ms with smoothing, the author's level table with hysteresis, one MAX7219 step every 200 ms; the strip in small steps | `bright.cpp` |
| Night quiet | while the display is off (schedule or MQTT), the info cycle and its downloads pause; Wi-Fi, NTP, MQTT, alarm keep working | `night.cpp` |
| Time after restart | the ESP32 system time survives a software restart — shown immediately (without the “synced” flag) | `timefix.cpp` |
| “Auto” summer time | last Sunday of March and October, 01:00 UTC | `timefix.cpp` |
| Wi-Fi debugging | log on TCP 23, ArduinoOTA; switched on the System page | `wdbg.cpp`, [wifi-debug.md](wifi-debug.md) |
| Crash cause | the core crash handlers (`--wrap`) store the cause, address and backtrace in RTC memory; after the restart — into the event log | `crash.cpp` |
| Main-loop watchdog | if `loop()` does not complete for 3 min — an event log entry and a restart | `guard.cpp` |
| Summer time in the web interface | Off / On / Auto on the “Time” page | `webui_patch.py` |

## Independence from the author's server

| What | Original 2.7.1 | Informer Clock UA |
|---|---|---|
| New version check | `goldart.ee/api/esp32/…` | `update/esp32.json` in this repository |
| Firmware file | the author's server, HTTP | GitHub, HTTPS, address with the version tag |
| Language packs (interface and display) | `goldart.ee/api/lang` | `lang/` in this repository |
| Change history (“What's New”) | `goldart.ee/api/changelog.json` | `update/changelog.json` |
| Sounds for the SD card, cases | `goldart.ee/api/files/…` | the [`files`](https://github.com/roman885-85/informer-clock-ua/releases/tag/files) release |
| Images, manual | `goldart.ee/web_images/…`, `goldart.ee/manual/` | `docs/images`, the project site |
| Home Assistant: manufacturer, model, version | Clock Informer | Informer Clock UA, model “based on Clock Informer by Semen_p” |

Version numbers are this project's own (1.x). The clock offers an update only to a **newer** version of this project; it
never sees the author's firmware, and clocks running the author's firmware never see this project's firmware. The
original's check that “the update address must be unchanged”, which restarted the clock, was removed together with the
address.

Third-party services the firmware talks to (as in the original, according to the user's settings): NTP
(`pool.ntp.org` by default), OpenWeatherMap, Weatherbit, Yandex Weather, GNews, NewsData, Frankfurter (rates),
CoinGecko, YouTube Data API, narodmon.ru, rzhunemogu.ru, ip-api.com and api.ipify.org (IP geolocation), internet
check — 8.8.8.8, 1.1.1.1, `www.msftconnecttest.com`.

## Core 1.0.4 and `--wrap`

The Arduino-ESP32 1.0.4 core is kept the same as in the original: the author's behaviour is reproduced on it. A few
of its weak spots are replaced at link time (`-Wl,--wrap=…` in `platformio.ini`) without modifying the core:

| Function | Why |
|---|---|
| `WiFiGenericClass::hostByName` | DNS through the lwIP thread, waiting for the result |
| `lwip_connect` | a blocking connect for at most `NET_CONNECT_TIMEOUT_S` |
| `settimeofday` | SNTP time-set counter: “the time really arrived” |
| `xt_unhandled_exception`, `panicHandler` | crash cause record in RTC memory |
| `log_printf` | core messages also go to the network log |

## Flash partitions

As in the author's firmware (`firmware/partitions_clock.csv`): `nvs` 0x9000 (20 KB), `otadata` 0xE000 (8 KB), `app0`
0x10000 and `app1` 0x1F0000 (1,920 KB each; OTA updates write to the free one), `spiffs` 0x3D0000 (192 KB:
`config.json`, language packs, sensor history, event log). This is why switching from the author's firmware keeps the
settings.
